# Review Log: Player Controller

## Review — 2026-11-28 — Verdict: NEEDS REVISION
Review mode: full · Workflow: full
Scope signal: M
Specialists: game-designer, systems-designer, qa-lead, unity-specialist, network-programmer, gameplay-programmer, ux-designer, creative-director (senior)
Blocking items: 7 | Recommended: 12
Summary: The core design is sound and traces to Pillars 1 and 2: no jump, sprint forward only, oxygen as the sprint cost, a slow that grows with pack fill. What blocks is the movement maths and the state machine under it. F4 does not reset vy on leaving the ground and counts gravity twice while sliding. Stepping down drops the player into Falling, which flickers the sprint flag. Frozen has no reason set. There is no per-frame order. Unit tokens break Game Data & Tuning's R5. Several ACs cannot pass at real frame rates. An MVP comfort floor is missing. Rulings: the networking blockers (the Place RPC with an epoch, a persistent or a respawned player object, the tick and NetworkVariable split) gate Tier 2a co-op, not the solo MVP, and go to an ADR-0001 amendment before co-op. Float vs double: GDT R3 already defines float as 64-bit, so only the narrowing at the engine boundary needs stating. The escape bracket is real, but its numbers belong to Pack and Creature AI and to playtest. AC26 must be rewritten as a time-to-catch target either way.
Prior verdict resolved: First review
Findings:
- [BLOCKING] Formulas F4: grounded vy = −ground_stick is never reset on leaving the ground, so a 2 m fall takes 0.47 s, not the 0.64 s in the example and AC13. Sliding adds gravity twice (vy and v_slide), never combines with or resets against F2, and is capped only at terminal 50 m/s. Use one slide vector along the slope with `slide_speed_max`, F2 off while sliding.
- [BLOCKING] Core Rules R2 / F4 / States: stepping down a 0.45 m step, or going downhill at sprint, flickers into Falling (ground_snap 0.1 m, ground_stick pulls about 0.03 m a frame), and each flicker drops the sprinting flag. Name the ground check (a SphereCast from the capsule bottom), snap down within `step_offset`, add about 0.1 s coyote grace.
- [BLOCKING] States and Transitions / R10: Frozen exits on "unpause" despite four causes. Use a set of freeze reasons (pause, saving, dead, launching or ending run). Add Sliding↔Falling and Inactive→Falling. Placement must not unfreeze. Define death in mid-air. R10's "velocity kept at zero" contradicts the Edge Case and AC18 (a paused fall resumes); R10 omits the Saving freeze (Session & Authority).
- [BLOCKING] Core Rules R3: no per-frame order (look, F1 and F2, ground, F4, one Move, rebuild v_h from the actual displacement, kill and bounds, bob, publish). Does F6 clamp keyboard look?
- [BLOCKING] Tuning Knobs: unit tokens break GDT R5 (`m_per_s`, `rad_per_s`, `rad_per_px`; degrees not allowed, so slope and FOV go to `rad`; no acceleration unit for gravity, so ask GDT's revision for `m_per_s2`). The `restart` keys give no reason (GDT R3); most can be `live`.
- [BLOCKING] Acceptance Criteria: AC8 and AC22 cannot pass at 60 fps (5 frames = 0.083 s), and F2's "5 frames (0.074 s)" has the same error. AC12's tolerance is below one frame at 30 fps. AC21 is a tautology in solo. AC13, AC16 and AC23 cannot be EditMode, "Playtest" is not a project story type, and AC25 reads FOV off a screenshot. Coverage gaps: live tuning swap, out of bounds, placement on load, sliding transitions, Inactive, F6 normal frame and dt = 0, terminal velocity, step-down, moving threshold. Boundaries should be 44°/46° and 0.44/0.46 m.
- [BLOCKING] Visual/Audio / R11 / UI Requirements: no MVP comfort floor. The FOV and head-bob settings are deferred to an unwritten system while bob defaults on. Add one "Reduce motion" setting (bob, sway, landing dip, shake), an FOV setting, and a keyboard turn speed setting (1.9 rad/s fixed; a 180° turn takes 1.65 s), or ship bob at 0 until they exist. AC27 must include motion-susceptible testers and a run session.
- [RECOMMENDED] Core Rules R9 / Edge Cases: there is no way out when stuck (V-crevices between steep slopes, pits deeper than 0.45 m, self-built enclosures). Add a stuck rule (re-place after N s with no net movement) and authoring rules for Mining, Building and Asteroid World. The creative director calls this a required addition, not a choice.
- [RECOMMENDED] Formulas F2: the rate is picked by comparing magnitudes, so speed sags on a 90° strafe and the reversal text is false. Pick by dot(v_h, target).
- [RECOMMENDED] Core Rules R4: any move.y > 0 sprints, so a near-sideways sprint works, and a half-push sprint (3.1 m/s) is slower than a walk yet costs oxygen and noise. Designer's choice: a move.y threshold of 0.7 and a full push.
- [RECOMMENDED] Core Rules R4 / R9: the sprint toggle has two owners (Input and Player Controller). Input should expose a clear call, the toggle should clear when move.y ≤ 0, and Build has no sprint.
- [RECOMMENDED] Edge Cases: the focus-loss case says "not paused", but Input and Session & Authority R9 auto-pause by default.
- [RECOMMENDED] Formulas F1 / Tuning Knobs: the escape bracket is too thin (14/16 slots: 4.30 vs 4.4 m/s, 100 s to close 10 m; AC26 cannot pass). Set time-to-catch targets and re-solve `full_pack_slow` and `burrower_speed` with Pack and Creature AI. "Fill" must be defined by Pack (slots or units). Designer's choices: linear or weight bands; a ramp that scales with fill.
- [RECOMMENDED] Open Questions 8: settle the full-pack slow at home now. The creative director recommends slowing In Run only (Pillar 5's unpacking payoff). Designer's decision.
- [RECOMMENDED] Tuning Knobs: ranges break their own contracts (`capsule_radius` max 0.5 vs the 0.9 m doorway; the `step_offset < capsule_height` check can never fail; `eye_height` up to 1.75 clips ceilings; gravity 9.81 is off its 0.1 step). Hardcoded values (0.1 m/s moving threshold, 0.15 s bob fade, landing dip, sway) should be knobs, and F5's `w` easing needs defining.
- [RECOMMENDED] Dependencies: Pack is not written. Name an injected Pack-load interface with an MVP stub, and say where `full_pack_slow` lives until Pack exists.
- [RECOMMENDED] Formulas F6 / AC16: `CharacterController.Move` already sweeps, so the clamp is about no teleport on a hitch, not tunnelling. Set `minMoveDistance` to 0. The `max_move_dt` min of 0.02 slows 30 fps play.
- [RECOMMENDED] Core Rules R1 / R8 / R9 (co-op, before Tier 2a; ADR-0001 amendment): a host→owner Place RPC with a placement epoch and NetworkTransform teleport; the CharacterController disabled while placing; a persistent vs respawned player object across scene loads; the Simulation tick vs NGO's tick; pitch and flags in an owner-writable NetworkVariable; the host reads the latest state, not the interpolated one; a range-check tolerance band; frozen and dead latency; the sprint flag read through a host-side interface.
- [RECOMMENDED] Player Fantasy / cross-system: forward-only sprint means running home without looking back, so the pursuer must be audible. Record this as a requirement on Creature AI and Audio. The no-jump rationale should name collision scope and Building, since a hop adds no horizontal speed.
- [RECOMMENDED] UI Requirements: the crosshair has no size, contrast or reach feedback, and its owner is unclear (R7 says no crosshair logic). Holding Shift while strafing fails silently.
