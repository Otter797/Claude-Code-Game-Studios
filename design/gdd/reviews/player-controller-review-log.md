# Review Log: Player Controller

## Review — 2026-11-28 — Verdict: NEEDS REVISION
Review mode: full · Workflow: full
Scope signal: M
Specialists: game-designer, systems-designer, qa-lead, unity-specialist, network-programmer, gameplay-programmer, ux-designer, creative-director (senior)
Blocking items: 7 | Recommended: 12
Summary: The core design is sound and traces to Pillars 1 and 2: no jump, sprint forward only, oxygen as the sprint cost, a slow that grows with pack fill. What blocks is the movement maths and the state machine under it. F4 does not reset vy on leaving the ground and counts gravity twice while sliding. Stepping down drops the player into Falling, which flickers the sprint flag. Frozen has no reason set. There is no per-frame order. Unit tokens break Game Data & Tuning's R5. Several ACs cannot pass at real frame rates. An MVP comfort floor is missing. Rulings: the networking blockers (the Place RPC with an epoch, a persistent or a respawned player object, the tick and NetworkVariable split) gate Tier 2a co-op, not the solo MVP, and go to an ADR-0001 amendment before co-op. Float vs double: GDT R3 already defines float as 64-bit, so only the narrowing at the engine boundary needs stating. The escape bracket is real, but its numbers belong to Pack and Creature AI and to playtest. AC26 must be rewritten as a time-to-catch target either way.
Prior verdict resolved: First review
Findings:
- [BLOCKING] Formulas F4: grounded vy = −ground_stick is never reset on leaving the ground, so a 2 m fall takes 0.47 s, not the 0.64 s in the example and AC13. Sliding adds gravity twice (vy and v_slide), never combines with or resets against F2, and is capped only at terminal 50 m/s. Use one slide vector along the slope with `slide_speed_max`, F2 off while sliding.
- [BLOCKING] Core Rules R2 / F4 / States: stepping down a 0.45 m step, or going downhill at sprint, flickers into Falling (ground_snap 0.1 m, ground_stick pulls about 0.03 m a frame), and each flicker drops the sprinting flag. Name the ground check (a SphereCast from the capsule bottom), snap down within `step_offset`, add about 0.1 s coyote grace.
- [BLOCKING] States and Transitions / R10: Frozen exits on "unpause" despite four causes. Use a set of freeze reasons (pause, saving, dead, launching or ending run). Add Sliding↔Falling and Inactive→Falling. Placement must not unfreeze. Define death in mid-air. R10's "velocity kept at zero" contradicts the Edge Case and AC18 (a paused fall resumes); R10 omits the Saving freeze (Session & Authority).
- [BLOCKING] Core Rules R3: no per-frame order (look, F1 and F2, ground, F4, one Move, rebuild v_h from the actual displacement, kill and bounds, bob, publish). Does F6 clamp keyboard look?
- [BLOCKING] Tuning Knobs: unit tokens break GDT R5 (`m_per_s`, `rad_per_s`, `rad_per_px`; degrees not allowed, so slope and FOV go to `rad`; no acceleration unit for gravity, so ask GDT's revision for `m_per_s2`). The `restart` keys give no reason (GDT R3); most can be `live`.
- [BLOCKING] Acceptance Criteria: AC8 and AC22 cannot pass at 60 fps (5 frames = 0.083 s), and F2's "5 frames (0.074 s)" has the same error. AC12's tolerance is below one frame at 30 fps. AC21 is a tautology in solo. AC13, AC16 and AC23 cannot be EditMode, "Playtest" is not a project story type, and AC25 reads FOV off a screenshot. Coverage gaps: live tuning swap, out of bounds, placement on load, sliding transitions, Inactive, F6 normal frame and dt = 0, terminal velocity, step-down, moving threshold. Boundaries should be 44°/46° and 0.44/0.46 m.
- [BLOCKING] Visual/Audio / R11 / UI Requirements: no MVP comfort floor. The FOV and head-bob settings are deferred to an unwritten system while bob defaults on. Add one "Reduce motion" setting (bob, sway, landing dip, shake), an FOV setting, and a keyboard turn speed setting (1.9 rad/s fixed; a 180° turn takes 1.65 s), or ship bob at 0 until they exist. AC27 must include motion-susceptible testers and a run session.
- [RECOMMENDED] Core Rules R9 / Edge Cases: there is no way out when stuck (V-crevices between steep slopes, pits deeper than 0.45 m, self-built enclosures). Add a stuck rule (re-place after N s with no net movement) and authoring rules for Mining, Building and Asteroid World. The creative director calls this a required addition, not a choice.
- [RECOMMENDED] Formulas F2: the rate is picked by comparing magnitudes, so speed sags on a 90° strafe and the reversal text is false. Pick by dot(v_h, target).
- [RECOMMENDED] Core Rules R4: any move.y > 0 sprints, so a near-sideways sprint works, and a half-push sprint (3.1 m/s) is slower than a walk yet costs oxygen and noise. Designer's choice: a move.y threshold of 0.7 and a full push.
- [RECOMMENDED] Core Rules R4 / R9: the sprint toggle has two owners (Input and Player Controller). Input should expose a clear call, the toggle should clear when move.y ≤ 0, and Build has no sprint.
- [RECOMMENDED] Edge Cases: the focus-loss case says "not paused", but Input and Session & Authority R9 auto-pause by default.
- [RECOMMENDED] Formulas F1 / Tuning Knobs: the escape bracket is too thin (14/16 slots: 4.30 vs 4.4 m/s, 100 s to close 10 m; AC26 cannot pass). Set time-to-catch targets and re-solve `full_pack_slow` and `burrower_speed` with Pack and Creature AI. "Fill" must be defined by Pack (slots or units). Designer's choices: linear or weight bands; a ramp that scales with fill.
- [RECOMMENDED] Open Questions 8: settle the full-pack slow at home now. The creative director recommends slowing In Run only (Pillar 5's unpacking payoff). Designer's decision.
- [RECOMMENDED] Tuning Knobs: ranges break their own contracts (`capsule_radius` max 0.5 vs the 0.9 m doorway; the `step_offset < capsule_height` check can never fail; `eye_height` up to 1.75 clips ceilings; gravity 9.81 is off its 0.1 step). Hardcoded values (0.1 m/s moving threshold, 0.15 s bob fade, landing dip, sway) should be knobs, and F5's `w` easing needs defining.
- [RECOMMENDED] Dependencies: Pack is not written. Name an injected Pack-load interface with an MVP stub, and say where `full_pack_slow` lives until Pack exists.
- [RECOMMENDED] Formulas F6 / AC16: `CharacterController.Move` already sweeps, so the clamp is about no teleport on a hitch, not tunnelling. Set `minMoveDistance` to 0. The `max_move_dt` min of 0.02 slows 30 fps play.
- [RECOMMENDED] Core Rules R1 / R8 / R9 (co-op, before Tier 2a; ADR-0001 amendment): a host→owner Place RPC with a placement epoch and NetworkTransform teleport; the CharacterController disabled while placing; a persistent vs respawned player object across scene loads; the Simulation tick vs NGO's tick; pitch and flags in an owner-writable NetworkVariable; the host reads the latest state, not the interpolated one; a range-check tolerance band; frozen and dead latency; the sprint flag read through a host-side interface.
- [RECOMMENDED] Player Fantasy / cross-system: forward-only sprint means running home without looking back, so the pursuer must be audible. Record this as a requirement on Creature AI and Audio. The no-jump rationale should name collision scope and Building, since a hop adds no horizontal speed.
- [RECOMMENDED] UI Requirements: the crosshair has no size, contrast or reach feedback, and its owner is unclear (R7 says no crosshair logic). Holding Shift while strafing fails silently.

## Review — 2026-11-28 — Verdict: NEEDS REVISION
Review mode: full · Workflow: full
Scope signal: M
Specialists: systems-designer, qa-lead, game-designer, unity-specialist, ux-designer, creative-director (senior)
Blocking items: 8 | Recommended: 13
Summary: Re-review of revision 1 (98e5252). Revision 1 fixes the freeze-reason model and the tuning units, and the registry matches the GDD (walk_speed, sprint_speed, step_offset, slope_limit_rad, full_pack_slow 0.5, move_target_speed). But the new per-frame order's step 8 feeds the actual displacement back into F2's ramp, so walking along a wall or up a slope gets slower as the frame rate rises. The sliding, grace and step-camera rules contradict each other or the comfort promise. The fixes stay inside R3, F2, F4, R2, R9 and the ACs, with no redesign; the next pass should be judged on one test: a 45° wall slide and a walkable uphill give the same speed at 30, 60 and 144 fps.
Prior verdict resolved: No. Resolved: #3 (freeze reasons, kept velocities, transitions, dead body falls) and #5 (units and `restart` reasons, against the committed GDT). Partly resolved and carried below: #1 (vy reset fixed; the slide contradiction remains), #2 (snap-down and grace added; the grace and steep-normal flicker remain), #4 (the order exists; step 8 adds new defects), #6 (most ACs rewritten; new defects), #7 (floor named; not binding, and the step camera pops).
Rulings: (a) step 8: F2 integrates the intended velocity with no feedback; the actual displacement feeds only *moving*, bob and the position report; v_h is zeroed only on a near head-on hit. Projecting out the hit normal alone still drifts (systems-designer over unity-specialist). (b) Game Data & Tuning's uncommitted revision 2 makes degrees the only angle unit. This GDD matches the committed GDT, so the conflict is a propagation item, not a blocker: when that revision lands, convert look_sens, key_turn, pitch_max, slope_limit and FOV in the same changeset and close Open Question 13 (`m_per_s2` now exists); the producer coordinates. (c) The camera pop blocks (ux over unity-specialist). (d) The run placement blocks; the stuck timer firing on a long slope is recommended. (e) The full-pack slow of 0.5 and the walk/sprint split are the designer's call, but the 1.9 m/s full-pack walk below `walk_speed`'s minimum of 2 must be reconciled.
Findings:
- [BLOCKING] Core Rules R3 step 8 / F2: the actual displacement ÷ dt fed back into the ramp makes speed depend on frame rate: a 45° wall slide at walk settles at 2.44, 1.22 and 0.51 m/s at 30, 60 and 144 fps (2.69 without the rebuild); uphill likewise if the CharacterController returns about cos²θ. F2 should integrate the intended v_h; store the impact speed before zeroing vy, or the landing dip never fires.
- [BLOCKING] Formulas F4 / R3 step 5: R3 says the slide replaces the downhill part of the velocity; F4 says only the uphill part is removed. Under F4, step 8 feeds the slide back (+0.64 m/s a frame at 60 fps on 50°). Pick "replaces", define v_s on entering Sliding, and define the downhill direction in a V (average the normals).
- [BLOCKING] Core Rules R3 step 8 / F6: step 8 divides by dt, but F6 allows dt = 0 (Unity's deltaTime at timeScale 0), so a NaN position reaches the host report. Guard it: run only mouse look and Publish, and keep the velocities.
- [BLOCKING] Core Rules R2 / States / F4: the grace says the body falls at once, but F4 keys its rules on state names and the state table gives Grounded the ground stick "including the grace" (−2 m/s for 0.1 s is 0.2 m, against 0.049 m from gravity). Key F4 on a physical airborne flag, and say whether air_control applies during the grace (AC15 depends on it).
- [BLOCKING] Core Rules R2 / States: Grounded→Sliding is immediate, and a sphere cast returns contact normals, so the edge of a 0.45 m foundation reads steep, drops the sprinting flag (oxygen and noise flicker) and starts the stuck timer. Confirm the face normal with a raycast, require a short dwell before Sliding, and cast with radius minus skin from higher up.
- [BLOCKING] Core Rules R2 / R11: snap-down and the controller's step-up move the camera up to 0.45 m in one frame, on every stair and foundation edge, which makes "no forced camera motion" false. Smooth only the eye's vertical offset (`eye_smooth_s` about 0.1 s), never the look direction, and say whether the view ray uses the raw or the smoothed eye.
- [BLOCKING] Core Rules R9: on a run, the stuck rule and out-of-bounds both place the player at the "nearest arrival point", which is the landing area by the ship. That is a free trip home with a full pack, and Edge Cases and Open Question 11 forbid it. On a run, place them at their last safe Grounded position.
- [BLOCKING] Acceptance Criteria:
  - Wrong as written: AC40 (Unity's Euler sign, and degrees), AC20 (vacuous: a 100 m fall lands at 44.3 m/s and never reaches 50), AC32 (contradicts R4: no sprint while Falling), AC44 ("8 s ± 1" allows 9 s).
  - Results decided by float rounding at exact boundaries: AC2 (move.y 0.70), AC23 (a 0.45 m step down), AC25 (0.09 and 0.11 s at 1/60), AC41 (a 0.15 s fade). Move the values off the boundary and state frame counts.
  - AC24 "never stop unexpectedly" cannot be measured.
  - AC45's mean hides the motion-sensitive testers, and no AC makes the comfort floor binding on an MVP build.
  - Missing: sliding transitions, and the angled wall slide at 30, 60 and 144 fps.
- [RECOMMENDED] Core Rules R3 / R10: Frozen returns before Publish, so the sprinting flag stays on through Saving, Launching Run and Ending Run. Publish both flags false while Frozen.
- [RECOMMENDED] Core Rules R10 / Dependencies: Session & Authority publishes one frozen flag with no reason, and Player Controller reads only that flag. R10 expects reasons and applies the local pause directly. The behaviour is the same, but align the interface text.
- [RECOMMENDED] Core Rules R9: the stuck timer fires on a legitimate long slope (3 m/s × 3 s is only 9 m). Count it only while net movement over 1 s is under 0.5 m; pause it while Frozen; replace the "one frame" overlap check with a time and name the overlap query.
- [RECOMMENDED] Formulas F1 / R5: a full-pack walk at 1.9 m/s is below `walk_speed`'s minimum of 2, and a full sprint (3.1) is below an empty walk (3.8), so players hold Sprint all the way home. Designer's call: split the slow by gait (walk 0.3, sprint 0.5). Add a mid-fill escape target. Take the starting gap from burrower emergence, not a fixed 10 m.
- [RECOMMENDED] Core Rules R4: auto-clearing the toggle surprises toggle users (stick drift to 0.69, a brief W release). Suspend the sprint instead of clearing it, clear after 0.25 s of zero Move, and add hysteresis (0.7 to enter, 0.6 to exit).
- [RECOMMENDED] Formulas F5 / R11: the sprint hand lowering pops 6 cm; ease it. State Reduce motion's scope (the lowering stays; placements fade). The "Unstuck" notice needs wording and a duration. Label the field of view setting in horizontal degrees.
- [RECOMMENDED] Formulas F4: leaving Sliding or a downhill run resets vy to 0, which throws away 2 to 4 m/s of downward speed (a visible float). Carry the last actual vertical speed.
- [RECOMMENDED] Tuning Knobs: skin width is unspecified, and radius 0.4 plus Unity's default skin of 0.08 is 0.96 m, too wide for the 0.9 m doorway. Add `skin_width_m` and the constraint `ground_snap_m < step_offset`. Unity's slopeLimit is in degrees. Fix the stepOffset wording.
- [RECOMMENDED] Core Rules / Player Fantasy / R12 / AC3: stale text: the lens bullet still says "35% slower, 6.2 × 0.65 = 4.0"; Pillar 3 still lists "no jump over a burrower" and R12 says each item changes escape speeds, both against the corrected jump rationale; AC3's 0.35 reads as the shipped value.
- [RECOMMENDED] Edge Cases / AC26: sprinting against a wall keeps the sprinting flag on, so oxygen drains at 0 m/s. Designer's decision.
- [RECOMMENDED] Acceptance Criteria coverage: the F5 fill hand-lowering term, the landing dip, R9's deep overlap, look before move, mouse look not clamped by F6, and Frozen→unfrozen re-checking the ground. AC11 and AC12 should state frames; AC15 should say "in the Falling state".
- [RECOMMENDED] Tuning Knobs (propagation): convert the angle keys to degrees if Game Data & Tuning's revision 2 lands with degrees only, and fix line 827 and Open Question 13 to match.
- [RECOMMENDED] Formulas F2 / F5 (nice-to-have): it is unclear whether a time of 0 under air_control means instant. 0.785 and 1.222 sit off their 0.017 step (D2 snaps them on the first click; 0.785 is just under 45°). The dip's 2 and 10 m/s constants are hardcoded. full_pack_accel_mult could also apply to turning. Ship bob off by default once the settings exist.
